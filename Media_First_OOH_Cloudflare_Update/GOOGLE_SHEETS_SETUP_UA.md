# Налаштування Google Sheets для Media First OOH

Ця версія читає всі вкладки Google-таблиці, зокрема приховані. Вкладка стає шаром карти, якщо в ній є заголовки міста та координат і хоча б один коректний рядок з координатами.

## 1. Обов'язкові колонки кожного шару

У кожній вкладці з рекламними об'єктами мають бути:

| Обов'язкова колонка | Допустимі заголовки |
|---|---|
| Місто | `Місто`, `Населений пункт`, `City`, `Location` |
| Широта | `Широта`, `Latitude`, `Lat` |
| Довгота | `Довгота`, `Longitude`, `Lon`, `Lng` |

Розмісти заголовки в одному з перших 20 рядків; рекомендовано — у першому. Один рядок = один об'єкт. Не додавай підсумкові рядки до діапазону об'єктів.

Для стабільного зв'язку з вибраними площинами додай постійний ID. Підтримуються заголовки `ID площини`, `Унікальний ID`, `Унікальний ідентифікатор`, `ID`, `Код площини`, `Новий Код`, `Код`, `Артикул`. Для нових шарів найкраще використовувати окрему колонку `ID площини` й не змінювати її для того самого об'єкта.

Якщо у вкладці немає стабільного ID, система формує складений ключ із назви вкладки, міста, адреси/назви, партнера, типу, сторони й формату. Якщо два об'єкти мають однакові значення цих полів, система попередить про дублікати; тоді потрібно додати унікальні ID.

## 2. Реєстр шарів (необов'язковий, але рекомендований)

Створи окрему вкладку з назвою `Налаштування шарів`. Вона може бути прихованою. У першому рядку додай заголовки:

| Назва вкладки | Назва шару | Колір | Форма | Маркер | Тип шару | Порядок | Активний |
|---|---|---|---|---|---|---:|---|
| брендовані площини | Брендовані | `#8B5CF6` | square | BF | media | 40 | Так |
| цифрові екрани | Digital screens | `#06B6D4` | pin | LED | media | 50 | Так |
| старий інвентар | Архів | `#94A3B8` | circle |  | media | 90 | Ні |

`Назва вкладки` має точно збігатися з назвою джерельної вкладки. Підтримувані форми: `circle`, `diamond`, `square`, `pin`; українські значення `коло`, `ромб`, `квадрат`, `мітка` теж розпізнаються. Тип шару: `media` або `restaurant` (для ресторанних об'єктів). `Маркер` — короткий текст до 8 символів.

Якщо вкладки немає в реєстрі, але вона має обов'язкові координатні колонки, система все одно додасть її автоматично з кольором і формою за замовчуванням. Реєстр потрібен для керування назвою, кольором, формою, порядком і вимкненням архівних/технічних вкладок.

Початкові стилі зберігаються:
- `національна ООН` — синій `#005EFF`, коло;
- `локальна` — зелений `#25FF08`, ромб;
- `адреси ресторанів` — окремий ресторанний шар KFC.

## 3. Фото та схеми

Колонки `Фото` та `Схема` підтримують прямі URL, формули `=HYPERLINK("https://...","Фото")` і rich-text links, якщо Google Sheets API повертає посилання для клітинки. Користувач може перейти до оригіналу навіть коли preview недоступний.

Фото проксіюються через Worker з allowlist доменів. Це зроблено для безпеки: новий домен партнера не буде автоматично допущений до server-side fetch. Якщо з'явився новий домен фото/схем, його потрібно окремо перевірити й додати до allowlist у `src/worker.js`. Сторінки, що вимагають авторизації або блокують ботів, не гарантовано віддаватимуть прев'ю.

## 4. Підключення таблиці

1. Візьми ID Google-таблиці з URL між `/d/` та `/edit`.
2. Задай його як `GOOGLE_SHEET_ID` у локальному `.dev.vars` для локальної перевірки або як Worker Secret у Cloudflare для production.
3. Підключи той Google-акаунт у платформі, який має доступ до таблиці.
4. Після OAuth натисни «Оновити з Google Sheets».

Не роби Google-таблицю публічною для читання: доступ надається підключеному Google-акаунту через OAuth `spreadsheets.readonly`.

## 5. Як система реагує на зміни інвентаря

- Додані рядки потрапляють до наступної синхронізації.
- Змінені поля оновлюються у D1.
- Рядки, яких більше немає у джерелі, прибираються після успішної перевірки й атомарної заміни активного інвентаря.
- Ключі об'єктів з постійним ID не залежать від номера рядка, тому сортування та вставка рядків не повинні змінювати їхні ідентифікатори.
- Якщо загальна кількість або кількість у конкретному шарі зменшується на 50% чи більше, ручна синхронізація просить підтвердження. Автоматична синхронізація в такому випадку не застосовує зміну й залишає попередній інвентар.
- Відкрита карта перевіряє зміну версії інвентаря кожні 60 секунд і оновлює точки без ручного перезавантаження сторінки.

Для Cloudflare Workers Free поточний код встановлює обережну межу 1 000 об'єктів на одну синхронізацію. Це не гарантія продуктивності: реальний час CPU треба перевірити на production. У Cloudflare Free ліміт CPU становить 10 ms для звичайного запиту та Cron; очікування відповіді Google/D1 не рахується як CPU time, але парсинг і обробка даних — рахується. Якщо інвентар наближається до ліміту або з'являється Error 1102, потрібна подальша оптимізація/пакетний механізм або Workers Paid.

## 6. Розклад

Cloudflare Cron у цьому проєкті налаштований на `0 6 * * *` (06:00 UTC щодня). Це 08:00 у Києві взимку та 09:00 влітку. Для ручного оновлення Admin використовує кнопку в інтерфейсі; щодня відкривати Terminal не потрібно.
