# Media First OOH Planning Platform — Cloudflare edition

Незалежна Cloudflare-копія Media First OOH Platform. Floot-проєкт не змінюється. Інтерфейс — Workers Static Assets, серверна логіка — Cloudflare Workers, база — D1. R2 наразі необов'язкове й не підключається, щоб не активувати окреме сховище до потреби.

## Стан пакета

- Підготовлено 336 початкових об'єктів: 194 національні площини, 70 локальних, 72 ресторани KFC.
- Початкові координати звірено з Excel; у seed-зрізі збережено 260 фото-посилань і 152 посилання на схеми.
- Admin/User, персональні вибірки, збережені програми, Excel-експорт і Gmail API закладені в коді.
- Google Sheets sync читає всі вкладки, у тому числі приховані, знаходить фактичні заповнені діапазони й визначає нові шари за координатними колонками.
- Є необов'язковий реєстр `Налаштування шарів` для назв, кольорів, маркерів, порядку та вимкнення вкладок.
- Ключі об'єктів стабільні за унікальними ID; синхронізація не прив'язана до номера рядка.
- Новий інвентар готується в staging-таблицях, перевіряється за кількістю та застосовується до D1 атомарною транзакцією. Якщо staging або commit не проходить, стара база лишається активною.
- Різке скорочення на 50% або більше вимагає підтвердження вручну; scheduled sync не застосовує таке скорочення.
- Відкрита карта перевіряє нову revision D1 кожні 60 секунд.
- Додано кнопку тестового Gmail-листа.

**Важливо:** офлайн-перевірки пакета пройшли, але реальний Google OAuth, Gmail delivery і production Cron ще потрібно протестувати у вашому Google/Cloudflare акаунтах. Не можна вважати пошту або Sheets повністю підключеними до проходження цих тестів.

## Що вже створено у вашому Cloudflare

За попередніми діями користувача віддалена D1 `media-first-ooh-platform` уже створена й містить 336 рядків з початкової імпортованої таблиці. У ній уже застосована тільки міграція `0001_initial.sql`. Нове оновлення додає `0002_dynamic_layers_and_safe_sync.sql`; воно не запускає повторний seed і не очищує 336 записів.

Поточний `wrangler.jsonc` у вашому Mac містить ваш власний D1 ID та не має R2 binding. Скрипт оновлення спеціально **не перезаписує** `wrangler.jsonc`, `.dev.vars`, `data/` або локальні дані.

## Локальна перевірка

```bash
npm install
npm run db:migrate:local
npm run test
npm run dev
```

У браузері відкрий `http://localhost:8787`. `.dev.vars` — локальний файл із секретами; ніколи не додавай його до ZIP, Git або чату.

## Google Sheets та Gmail

Дивись окрему інструкцію [GOOGLE_SHEETS_SETUP_UA.md](./GOOGLE_SHEETS_SETUP_UA.md). Google OAuth потребує Web application OAuth Client ID, redirect URI та ввімкнених Sheets API і Gmail API.

Запитувані scopes: `openid`, `email`, `spreadsheets.readonly`, `gmail.send`. Підключений Admin-акаунт має мати доступ до джерельної таблиці. Один підключений Admin Gmail використовується як відправник для команди; це не читання inbox, а надсилання листів.

Для зовнішнього OAuth-застосунку в режимі Testing refresh token для scopes понад базову ідентифікацію Google може спливати через 7 днів. Для постійної роботи потрібно правильно налаштувати OAuth consent та тип аудиторії (наприклад Internal для відповідного Google Workspace домену) або пройти потрібну Google verification. Не вважайте Gmail автоматично постійно підключеним до завершення live-тесту.

## Розклад та оновлення

Cloudflare Cron: `0 6 * * *` (06:00 UTC щодня; 08:00 Київ узимку / 09:00 влітку). Ручне оновлення виконується кнопкою Admin. Користувачі з уже відкритою картою отримують нові дані автоматично в межах 60 секунд після успішної синхронізації. Щодня запускати Terminal не потрібно.

Для Cloudflare Workers Free встановлена обережна межа 1 000 об'єктів на одну синхронізацію. Free тариф дає лише 10 ms CPU на HTTP запит та Cron; парсинг масиву рахується у CPU. Для початкових 336 записів очікується помірне навантаження, але фактичну тривалість треба перевірити після deploy. Якщо кількість підходить до 1 000 або з'являється Error 1102, треба пакетний механізм або Workers Paid.

## R2 / передперегляд фото

R2 наразі вимкнено. Посилання фото та схем відкриваються через захищений Worker proxy, але без R2 успішні зображення не кешуються у власному bucket. Для увімкнення кешу пізніше потрібно створити bucket і додати binding `ASSETS_BUCKET`. R2 не потрібен для синхронізації, ролей, карти, аналітики, Excel або Gmail.

Preview залежать від партнерських сайтів: закриті сторінки, авторизація або антибот-захист можуть завадити завантаженню. Новий партнерський домен треба окремо перевірити й додати до allowlist у `src/worker.js`.

## Публікація (після тестів)

1. Застосувати migration 0002 до local і remote D1.
2. Перевірити parser tests і відкриту локальну карту.
3. Виконати перший deploy і створити окремого Production Admin у remote D1 (локальний Admin не переноситься автоматично).
4. Після отримання workers.dev адреси додати `https://<ваш-домен>.workers.dev/api/google/callback` до Google OAuth Authorized redirect URIs.
5. Налаштувати Worker Secrets `BOOTSTRAP_TOKEN`, `TOKEN_ENCRYPTION_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_SHEET_ID`.
6. Підключити Google, виконати sync preview, ручну синхронізацію, перевірити тестовий лист, потім Cron і доступи чотирьох людей.

Не запускай `npm run db:seed:remote` повторно після початкового імпорту. Ця команда — початковий seed із файлу, а не місячне оновлення. Для наступних оновлень використовується Google Sheets sync.

## Автономні тести

```bash
npm run test
```

Перевіряються синтаксис Worker/Sheets parser/inline frontend scripts, D1 migration 0001 + seed + 0002 у SQLite, початкові 336 записів, фото/схеми, динамічні вкладки, прихований реєстр шарів, відключення архівної вкладки, стабільні ID та формули HYPERLINK. Це офлайн-перевірка пакета, а не підтвердження live Google OAuth чи Gmail delivery.
