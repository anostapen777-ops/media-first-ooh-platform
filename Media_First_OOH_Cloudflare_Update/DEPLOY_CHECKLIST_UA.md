# Media First OOH — checklist перед публікацією

## Технічне оновлення
- [ ] Застосувати update patch у наявній папці проєкту (не перезаписувати `wrangler.jsonc` і `.dev.vars`).
- [ ] `npm run db:migrate:local` — застосувати 0002 до локальної D1.
- [ ] `npm run db:migrate:remote` — застосувати 0002 до віддаленої D1; не запускати повторний seed.
- [ ] `npm run test` — усі офлайн-тести зелені.
- [ ] `npm run dev` — перевірити локальну карту, шари, фільтри, деталі, вибір, Excel.

## Google Sheets
- [ ] Переконатися, що Google-таблиця доступна підключеному Admin Google-акаунту.
- [ ] Перевірити координатні заголовки в усіх вкладках із даними.
- [ ] За потреби створити `Налаштування шарів` і перевірити кольори/форми/активність.
- [ ] Додати постійний `ID площини` у нові шари.
- [ ] Налаштувати Google Sheets API й OAuth scopes.
- [ ] Провести preview й ручну синхронізацію; звірити підсумок і шари.
- [ ] Перевірити реакцію на вставку/сортування/зменшення тестового інвентаря.

## Gmail
- [ ] Увімкнути Gmail API.
- [ ] Налаштувати OAuth redirect URI для фактичного workers.dev домену.
- [ ] Підключити Google у платформі.
- [ ] Надіслати тестовий лист кнопкою «Тест Gmail» і перевірити Inbox/Sent.
- [ ] Надіслати тестову Excel-програму на інший контрольований email.
- [ ] Перевірити OAuth consent status; не залишати зовнішній застосунок у Testing для постійного використання без розуміння 7-денного refresh-token обмеження.

## Production
- [ ] Виконати перший `npm run deploy` лише після локальних тестів.
- [ ] Створити окремий Production Admin у remote D1 — локальний користувач не переноситься.
- [ ] Додати Worker Secrets.
- [ ] Перевірити Cron execution о 06:00 UTC і last sync статус.
- [ ] Створити ще 3 користувачів і перевірити ролі Admin/User.
- [ ] Перевірити, що сторінка оновлюється після зміни revision у D1 (не пізніше 60 секунд).
- [ ] Тільки після всіх перевірок передати платформу команді.

## Важливі правила
- [ ] Не надсилати `.dev.vars`, OAuth client secret, bootstrap token чи encryption key у чат.
- [ ] Не запускати `db:seed:remote` після початкового імпорту.
- [ ] Різке скорочення на 50%+ — тільки після перевірки й підтвердження Admin.
- [ ] Якщо Workers Free досягає CPU 10 ms ліміту, не збільшувати частоту Cron без оптимізації.
